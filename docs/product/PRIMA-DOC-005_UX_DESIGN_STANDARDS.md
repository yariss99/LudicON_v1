# PRIMA-DOC-005  
# UX Design Standards

**The User Experience Framework of PRIMA**

Adopted as the permanent experience reference for how every interaction within PRIMA should feel, behave, and support educational work.

---

# Preamble

The objective is not ornamental beauty.  
The objective is **reduced cognitive load, increased teacher confidence, and improved educational productivity**—under calm professional control.

Beauty may accompany clarity.  
Complexity that impresses designers while exhausting teachers is failure.

Core question for every section:

> **Does this interaction make pedagogical craft clearer, calmer, and more controllable under time pressure?**

---

# PART I — UX Philosophy

### 1.1 Experience as pedagogical infrastructure
The interface is part of teaching conditions. Every friction, ambiguity, or coercive pattern taxes educational quality.

### 1.2 The Teacher Studio experience
PRIMA should feel like a professional atelier: quiet enough to think, structured enough to finish, respectful enough to trust.

### 1.3 Clarity over spectacle
Visual intensity never outranks intelligibility. Hierarchy exists so teachers can find the job of the screen in seconds.

### 1.4 Complexity behind the curtain
Instrumental complexity is absorbed by the system. Teachers meet progressive power, not sprawling obligation.

### 1.5 Dual value in interaction
Every mandatory step must earn Dual Value (teacher effort ↓ and learning opportunity ↑) or be removed.

### 1.6 Assistance as calm counsel
Where assisting intelligence appears, it is labeled as counsel, editable, explainable, and never disguised as already-approved work (PRIMA-DOC-004).

### 1.7 Access is experience
An interface that excludes by perception, motor, or cognitive barrier is incomplete—regardless of visual polish.

### 1.8 Emotional contract
PRIMA owes teachers confidence, calm, support, respect, and control. Designs that produce confusion, coercion, or contempt fail this Framework.

# PART II — Core UX Principles

Fourteen permanent principles. Each binds product, design, and delivery.

---

### UX-01 — Clarity before density
**Meaning.** Teachers must understand the screen’s job before they see its richness.  
**Implication.** Prefer clear hierarchy over packed capability.  
**Measure.** New users identify the primary objective within seconds on core screens.

### UX-02 — One primary action per screen
**Meaning.** Each screen has one dominant job and one dominant action.  
**Implication.** Secondary actions are visually quieter; tertiary actions are progressive.  
**Measure.** Dual-value / single-job review passes before release.

### UX-03 — Reduce cognitive load
**Meaning.** Minimize simultaneous decisions, competing foci, and unnecessary memory demand.  
**Implication.** Defaults carry competence; copy stays short; decoration stays restrained.  
**Measure.** Core tasks require fewer concurrent choices than prior baseline.

### UX-04 — Predictable navigation
**Meaning.** Movement through the studio behaves as expected.  
**Implication.** Back means back; labels stay stable; wayfinding is consistent across modules.  
**Measure.** Teachers can return to prior state without disorientation.

### UX-05 — Visible feedback
**Meaning.** The system acknowledges waiting, success, failure, and saved state honestly.  
**Implication.** No silent success; no ambiguous hanging.  
**Measure.** Every critical action has an observable outcome state.

### UX-06 — Progressive disclosure
**Meaning.** Power appears when needed; calm path remains first.  
**Implication.** Advanced options do not crowd the primary job.  
**Measure.** Essential path completable without opening advanced panels.

### UX-07 — Consistency builds trust
**Meaning.** Recurring patterns teach the product once.  
**Implication.** Shared interaction grammar across modules; unjustified exceptions rejected.  
**Measure.** Pattern reuse documented; one-off inventions require justification.

### UX-08 — Accessibility by default
**Meaning.** Access is designed into critical paths from the start.  
**Implication.** Keyboard, structure, contrast, and alternatives are not late polish.  
**Measure.** Critical paths pass Accessibility Gate criteria.

### UX-09 — Teacher confidence over visual complexity
**Meaning.** Confidence is the primary aesthetic of PRIMA.  
**Implication.** Refuse visual systems that look advanced while feeling uncertain.  
**Measure.** Teachers report knowing what will happen next on core flows.

### UX-10 — Forgiving interactions
**Meaning.** Mistakes are recoverable where risk exists.  
**Implication.** Undo, confirm-on-risk, and recovery paths are designed deliberately.  
**Measure.** Destructive or high-impact actions offer recovery or explicit confirmation.

### UX-11 — Every interaction creates value
**Meaning.** Empty motion is product debt.  
**Implication.** Justify every mandatory click, field, and interruption.  
**Measure.** Feature review can defend each required step; undefended steps are cut.

### UX-12 — Honest states over false completeness
**Meaning.** Empty, loading, partial, and error states are designed as first-class experiences.  
**Implication.** Never pretend unfinished paths are whole.  
**Measure.** Core screens define empty / loading / error / success deliberately.

### UX-13 — Plain professional language
**Meaning.** Words are part of the interface architecture.  
**Implication.** Accessible, non-clinical, non-shaming copy by default.  
**Measure.** Critical labels are restatable by teachers without jargon decoding.

### UX-14 — No dark patterns
**Meaning.** Persuasion that tricks, shames, or disguises commitment is prohibited.  
**Implication.** Accept / modify / reject remain free; urgency must be true.  
**Measure.** Dark-pattern review finds none on commitment and recommendation surfaces.

# PART III — Interaction Standards

### 3.1 Navigation
- Primary destinations are few, named by teacher jobs, and stable.  
- Current location is always knowable.  
- Deep work preserves a clear exit and return.  
- Navigation never hijacks pedagogical commitment.

### 3.2 Forms
- Ask only what the job requires now.  
- Group related fields; reveal advanced fields progressively.  
- Labels are visible; errors sit next to the field and explain repair.  
- Defaults prefer inclusive competence over blank obligation.

### 3.3 Search
- Search results prioritize educational relevance and recent professional context.  
- Empty search results explain next steps.  
- Filters reduce noise without multiplying complexity by default.

### 3.4 Creation flows
- Creation begins with intention, not with ornamental templates alone.  
- Steps are few; each step has one job.  
- Teachers can pause and resume without losing authorship.  
- Drafts remain distinct from approved work.

### 3.5 Editing
- Edit in place where safe; isolate high-risk edits with clear scope.  
- Changes are attributable to teacher action.  
- Assistance offers edits as proposals, not silent rewrites.

### 3.6 Saving
- Save behaviour is predictable: explicit or clearly auto-saved with visible status.  
- Teachers never wonder whether work persists.  
- Save failures are loud, recoverable, and non-blaming.

### 3.7 Undo and recovery
- Reversible actions prefer undo.  
- Irreversible actions require clear warning and, where appropriate, confirmation.  
- Recovery of last approved state is available for high-impact changes.

### 3.8 Notifications
- Notify only when action or awareness creates value.  
- Tone is calm and professional; volume is restrained.  
- Notifications never coerce acceptance of AI recommendations.  
- Teachers can complete core work without notification theatre.

### 3.9 Errors
- Errors explain what happened, how to fix it, and that the teacher is not at fault by default.  
- Preserve entered work wherever possible.  
- Never use shame, humor at the teacher’s expense, or dead ends.

### 3.10 Loading and waiting
- Waiting is acknowledged immediately.  
- Progress communication is honest; indeterminate waits do not pretend precision.  
- Long waits offer cancel or safe background continuation where feasible.  
- Motion during wait is restrained and never the sole status channel.

### 3.11 Empty states
- Empty is instructional: what this space is for, and the single best next action.  
- Empty states do not fill with decorative clutter or false content.  
- First-run empty states teach the craft path, not marketing.

### 3.12 Recommendations and assistance surfaces
- Counsel is visually distinct from approved work.  
- Accept / modify / reject are first-class and equal in dignity.  
- Educational rationale is available at decision time (PRIMA-DOC-004).  
- Silence is preferred over low-value insistence.

### 3.13 Confirmation and commitment
- Confirm when risk warrants (loss, irreversibility, learner-facing publish).  
- Do not confirm for ceremony.  
- Commitment language is plain: what becomes true after this action.

# PART IV — Accessibility Standards

Accessibility is a default duty, not an optional theme.

### 4.1 Alignment with WCAG principles
PRIMA commits to the durable WCAG principles:
- **Perceivable** — information can be perceived through multiple senses as needed  
- **Operable** — interface components can be operated by diverse means  
- **Understandable** — information and operation are intelligible  
- **Robust** — content remains interpretable by a wide range of user agents and assistive technologies  

Critical paths must meet the Accessibility Gate defined by governing release practice, aligned to these principles.

### 4.2 Keyboard accessibility
All critical actions are reachable and operable by keyboard alone, with visible focus and logical order.

### 4.3 Screen readers and structure
Meaningful structure (headings, labels, names, roles, and status messages) allows assistive technologies to convey the job of the screen and the outcome of actions.

### 4.4 Color independence
Meaning is never carried by color alone. Status, errors, and required distinctions use additional cues (text, pattern, icon with text alternative).

### 4.5 Readable typography
Text is readable under professional conditions: adequate size, spacing, contrast, and line length for sustained teaching work. Decorative type never compromises comprehension of critical content.

### 4.6 Motor accessibility
Targets for critical actions are adequately sized and spaced. Timing constraints do not lock teachers out of completing professional tasks without alternative.

### 4.7 Cognitive accessibility
- Plain language on critical paths  
- Consistent patterns  
- Clear errors and next steps  
- Minimized simultaneous decisions  
- Avoidance of unnecessary motion and interruption  

### 4.8 Motion and vestibular care
Motion is purposeful and restrained. Essential information is never motion-only. Teachers can complete work without dependence on non-essential animation.

### 4.9 Inclusive language in the interface
Copy avoids deficit labeling of learners, clinical tone by default, and shaming of teachers (PRIMA-DOC-003 · PRIMA-DOC-004).

### 4.10 Gate rule
Accessibility regressions on critical paths block release.

# PART V — Emotional Design

PRIMA should make teachers feel:

### 5.1 Confident
They know the job of the screen and the consequence of the next action.  
**Design contribution:** clear hierarchy, honest feedback, predictable navigation.

### 5.2 Calm
The studio does not shout, crowd, or panic.  
**Design contribution:** restraint, quiet waiting, limited notification volume, breathing space.

### 5.3 Supported
Help arrives as counsel without takeover.  
**Design contribution:** explainable recommendations, progressive power, useful empty states.

### 5.4 Respected
Tone and structure honour vocation.  
**Design contribution:** professional language, no shame patterns, no deskilling rituals.

### 5.5 In control
Authorship remains theirs.  
**Design contribution:** editability, accept/modify/reject, undo, visible draft vs approved.

### 5.6 Emotional anti-goals
PRIMA must not make teachers feel hurried by false urgency, incompetent by opaque systems, watched by surveillance aesthetics, or coerced by recommendation pressure.

### 5.7 Emotional test
If removing visual decoration improves calm and clarity, decoration was noise.  
If removing a step improves confidence without harming learning quality, the step was waste.

# PART VI — UX Review Checklist

Mandatory before every release that changes screens, workflows, interactions, or navigation.

### 6.1 Purpose and load
- [ ] Primary objective of each changed screen is singular and obvious  
- [ ] One dominant action is clear  
- [ ] Mandatory steps are Dual-Value justified  
- [ ] Cognitive load is lower or equal with no clarity loss  

### 6.2 Interaction integrity
- [ ] Navigation remains predictable; location is knowable  
- [ ] Save / persistence behaviour is visible and trustworthy  
- [ ] Undo or confirm-on-risk exists where appropriate  
- [ ] Empty, loading, error, and success states are designed  
- [ ] Notifications are necessary and calm  

### 6.3 Assistance surfaces (if present)
- [ ] Drafts distinct from approved work  
- [ ] Accept / modify / reject available without penalty  
- [ ] Educational rationale available at decision time  
- [ ] No dark patterns or coercive urgency  

### 6.4 Accessibility
- [ ] Keyboard operable on critical path  
- [ ] Structure and names support assistive technologies  
- [ ] Color is not the sole meaning channel  
- [ ] Typography and targets meet readable/operable expectations  
- [ ] Cognitive accessibility: plain language, consistency, clear repair  

### 6.5 Emotional and Charter alignment
- [ ] Experience supports confidence, calm, support, respect, control  
- [ ] No shame, surveillance aesthetics, or contemptuous copy  
- [ ] Consistent with PRIMA-DOC-002 Teacher Experience Standard  
- [ ] No conflict with PRIMA-DOC-003 dignity / PRIMA-DOC-004 oversight  

### 6.6 Necessity
- [ ] Would removing this interaction improve calm or clarity? If yes → redesign or remove  

### 6.7 Decision rule
Any unchecked critical item returns the design to iteration.  
Accessibility Gate or dark-pattern findings block release.  
Rubber-stamp reviews are non-compliant.

---

# Closing

PRIMA’s experience standard is demanding and simple:

**Clear job. One dominant action. Calm feedback. Recoverable mistakes. Access by default. Teacher in control.**

Interfaces that merely look finished are not finished.  
Interfaces that make educational work humanly possible are finished.
